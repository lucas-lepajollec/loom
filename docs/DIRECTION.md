# Product direction

Loom focuses on Local/Cloud models, engines, discussions and Brain. The removal
of native coding harnesses reduces installer, protocol, account and permission
complexity. It does not remove generic tools, skills, MCP, terminals, machine
connections, voice, policy, notifications or engine management.

Priorities: predictable local/cloud execution, responsive mobile interaction,
clear context ownership, durable encrypted credentials, safe remote control,
free regression coverage and a smaller maintenance surface. Consolidate existing
behavior before adding routing or a knowledge graph.

External coding applications may consume inference through `/v1` or connect to
the authenticated MCP gateway manually. Loom does not manage their accounts,
configuration files or private execution state. This is interoperability, not
a return of an internal harness layer.

See [architecture principles](architecture-principles.md),
[roadmap](ROADMAP.md) and [migration](harness-retirement.md).
