# Interface languages

Loom's web interface supports English and French. Choose **Settings › General ›
Appearance › Langue / Language** (or **Réglages › Général › Apparence**) to switch
immediately, without reloading or discarding drafts. French keeps its existing
wording and both languages use the same components and styles.

The initial language comes from `loom-lang` in localStorage, falling back to
`navigator.language`: `fr*` selects French, everything else selects English.
Startup then reads the shared `lang` preference from `/api/prefs`. An explicit
selection made during that read takes precedence. Selecting a language updates
localStorage and the document language immediately and sends only
`{"lang":"en"}` or `{"lang":"fr"}` to the existing preference endpoint. Writes
are serialized; failed saves leave the browser selection intact and show a
notice. A server preference applies to other devices when they next open Loom.

## Adding interface copy

Import `t` from `js/core/i18n.js` and add matching keys to `js/i18n/fr.js` and
`js/i18n/en.js`. These are plain objects with flat keys grouped by feature.
French values must preserve the original text. Translate entire sentences
where possible, including variables rather than building grammar in code.

```js
t('chat.composer.placeholder');
t('runtime.copy.acp_custom', { command: 'ssh' });
t('n_models', { n: 2 });
```

Variables use `{name}`. Plural entries have `one` and `other` forms selected by
`Intl.PluralRules` for the current language. `locale()` supplies date/number
formatting. Shared functional components subscribe to language changes through
`core/lib.js`; memoized translated content must include `getLang()` in its
memo dependencies. Translated module-level catalogs use property getters or
functions so labels are evaluated in the current language.

`tSource` translates known Loom-owned copy from server catalogs (curated engine
parameters, runtime descriptions and engine phases). Unknown catalog text stays
as supplied. Never apply it to API errors, user content, model IDs, tool output
or native logs; these remain verbatim. It doesn't change configuration values,
commands or model-visible conversation text.

Run `make check-ui` to syntax-check every native module and run the UI tests.
The i18n tests check matching dictionary keys, plural forms and variables, every
literal translation key, and French-looking text/attributes in nested `html`
templates. Justified exceptions belong in
`internal/loom/ui/tests/i18n-allowlist.json` with an exact file, literal and
reason; unused exceptions fail the test. Runtime tests cover language defaults,
persistence, rapid changes, late preference reads and catalog/component identity.
