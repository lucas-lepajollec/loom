# Product, security and cleanup audit — November 2026

**Résumé français.** Audit du 18 novembre 2026 (code, sécurité, code mort, CSS,
dépendances) avec Codex en lecture seule et des outils statiques. Trois failles
corrigées : outils non proposés exécutables dans les discussions locales, outils
MCP masqués appelables par leur nom, lecture de pages pouvant viser la machine
ou le réseau local. 133 fonctions Go et 282 règles CSS mortes retirées. Ajout de
la reprise automatique des sessions Claude à la remise à zéro des quotas
(fonction de Codeman). Les pistes produit sont en fin de document.

## 1. Method

- Snapshot: `main` at `807532b` plus this branch.
- Read-only Codex review of security, dead code, performance and
  maintainability; every security finding below was re-read in the source and
  covered by a new deterministic test before being fixed.
- `deadcode -test ./...` (golang.org/x/tools) for Go functions unreachable from
  any binary or test; cross-builds for Linux, Windows and macOS because the
  tool only sees the host build tags.
- A class-reference scan of `ui/next/css` against `ui/next/js` and
  `index.html`, keeping classes generated by xterm.js and classes built from a
  prefix (`'st-' + state`).
- `govulncheck ./...`: no vulnerable symbol reachable (one advisory in a
  required module whose affected code is not called).

## 2. Security findings (fixed)

| Finding | Risk | Fix |
| --- | --- | --- |
| The local tool loop dispatched any tool name the model produced, including `bash`, `write` and memory tools that the discussion never offered. | Text injected into the model's context (web page, file, MCP result) could run a shell command with the agent mode off. | Only advertised tools run; others return a refusal to the model (`llm_client.go`, `llm_tool_gate_test.go`). |
| `MCPManager.Call` resolved any registered tool, including tools hidden by the user and servers disabled since discovery. Cloud turns reached it directly. | Hidden or disabled MCP tools stayed callable by name. | The current configuration is re-read on each call (`tools/mcp_pool.go`, test in `mcp_pool_test.go`). |
| `web_open` / `web_read` / `web_grep` fetched any URL, and the Go client followed redirects without a destination check. | Model-driven SSRF to loopback services (Loom, Codeman, engines) or the LAN. | Public-address dialer checked at connect time (covers redirects and DNS rebinding) and a pre-check before handing a URL to Crawl4AI (`web_fetch_go.go`, `web_fetch_public_test.go`). |

Remaining, not fixed here: generic policy rules (`docs/policy.md`) are enforced
on the MCP gateway but not on the in-app chat tool loop. The loop now runs only
the tools the user enabled for the discussion; applying per-command and
per-path policy there is a separate change.

## 3. Cleanup

- 133 Go functions unreachable from binaries and tests removed (mostly
  `*_compat.go` wrappers left by the retired coding-harness integration),
  one emptied file deleted. Platform helpers used only by Windows builds kept.
- 282 CSS rules whose selectors only target classes no screen uses removed
  (retired native-agent, catalog, history and memory panels).
- Product docs aligned with the Agents module (`VISION.md`, `ROADMAP.md`).

## 4. Quotas: reset handling

Codeman already detects a Claude usage-limit pause, parses the reset time and
sends `continue` when the limit resets (`/api/sessions/:id/auto-resume`, SSE
`session:limitPauseScheduled`, `session:limitResume`). Loom now uses it instead
of reimplementing it:

- per-session switch in the Info panel, with the planned resume time;
- a default for new Claude sessions (Agents › Settings), on unless turned off;
- a `limited` session state (amber) in the sidebar, grid and overview;
- Activity › Quotas lists paused sessions and says when a used-up window is
  available again.

## 5. Product observations

- Breadth: models (local, cloud, engines, nodes, API, voice), Agents
  (Codeman), Brain, terminals, machines, workspaces, tasks, bench. Several
  surfaces overlap: Loom terminals and Codeman shell sessions; workspaces and
  projects.
- The link between Brain and agents already exists technically: Loom's MCP
  gateway exposes `brain_search`, `brain_read`, `brain_write`, `brain_edit` and
  `brain_pack`; Codeman can register an MCP server in each CLI's own config
  (opt-in MCP sync). Nothing in the UI connects the two yet.
- Navigation: section tabs are a 13 px segmented control; on phones the Agents
  tab row is cut and pages stack two tab rows. Design proposals are tracked
  outside this repository.
