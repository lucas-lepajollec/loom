        Choisir un autre moteur
        
      

      
Windows, macOS et Linux. GPU NVIDIA (CUDA), AMD (ROCm / HIP ou Vulkan), Apple (Metal) et Intel (Vulkan) — sinon le CPU. Le zip officiel suit le système ; compiler llama.cpp donne le backend natif (CUDA Linux, HIP…).

      

        
Lier un llama-server déjà installé

        
Pointe vers un binaire déjà présent. Loom le lance tel quel, sans le copier. Si les sources llama.cpp sont au-dessus, c’est un projet complet (mises à jour par git + compilation).

        

          
          
          
        

      

      

        
Installer llama-server

        
Binaire officiel, sans les sources. Suffit pour chatter. llama.cpp complet peut être ajouté ensuite. Zip : CUDA sur Windows NVIDIA, Metal sur macOS, ROCm ou Vulkan sur Linux, sinon CPU.

        

        

          
        

      

      

        
Installer llama.cpp complet

        
Clone et compilation dans le dossier indiqué. Autonome : llama-server se lance aussi sans Loom. Backend détecté : CUDA, HIP/ROCm, Metal, Vulkan ou CPU.

Téléchargements du hub?Dossier où atterrissent les .gguf téléchargés depuis Modèles (et les liens collés). Il est aussi parcouru pour les fichiers déjà présents. Windows, macOS et Linux : coller un chemin local.

    

      
      

        
        
      

    

    
Dossiers de modèles?Dossiers où Loom cherche les .gguf déjà sur le disque. En liant un llama-server, le dossier models voisin est ajouté s’il en contient. Distinct du dossier de téléchargement du hub, sauf s’il est choisi ci-dessus.

    

      

      

        
        
      

    

    
    
Service du moteur?Démarre, redémarre ou arrête llama-server — le processus qui charge le modèle et répond. Un redémarrage recharge le modèle du preset actif (quelques secondes à quelques minutes selon sa taille).
